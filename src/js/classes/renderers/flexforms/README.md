# Флейвор «форма-ТСД»

`! как форма-тсд` — предпросмотр формы ТСД в рамке корпуса терминала и выгрузка
конфига JSON, который расширение 1С подставляет в оболочку ТСД вместо
`<data id="form-params">`.

Синонимы директивы (после `normalizeFlavorName`: без `-`, `_`, пробелов, нижний
регистр): `как тсд`, `as flexforms`, `как сканер`.

## Поток данных

```
разметка ЯРБП
   │  YarbpLexer + YarbpParser
   ▼
AST
   │  ast-converters/FlexFormsConvertor.js  (YarbpFlexFormsConverter)
   ▼
IR формы (JSON — тот же формат, что читает движок ТСД)
   │  flexforms/FlexFormsPage.js
   ├─ buildFormPage   ──►  HTML-страница  ──►  iframe[srcdoc] в рамке ТСД  (предпросмотр)
   ├─ buildFormConfig ──►  <заголовок>.json  ──►  файл для 1С              (кнопка «JSON»)
   └─ flexforms_mock_server.py ──► локальный сервер ──► хук / отправка / health (кнопка «мок-сервер»)
```

Страница формы — это `редизайн/kb8-inventory-redesign.html`:
тот же CSS, тот же движок (хук ШК, приёмники, таблицы, отправка, флаги, тема,
клавиатура, индикатор сети). В движок добавлена поддержка `.сервис` (склейка
относительных адресов и строка сервера в шапке). Отличия остального — про
подстановку: в `<data id="form-params">` лежит IR, собранный из разметки
редактора, а не форма-образец, а в предпросмотре к странице добавлены два
коротких скрипта (снимок `localStorage` и автофокус — см. п. 2 ниже).

Страница нужна только предпросмотру. Наружу редактор отдаёт **не её, а конфиг
JSON**: самодостаточную страницу для ТСД собирает расширение 1С, подставляя
конфиг в оболочку редизайна вместо `<data id="form-params">`. Поэтому текст
конфига и текст, который получает предпросмотр, — один и тот же
(`serializeFormIR`), это сверяет тест.

## Пример в редакторе

В папке «Примеры» редактора есть файл **«Форма ТСД»** (`FileManager`,
`builtin-9`) — компактный пример актуальной разметки. Значения, которые
подставляет конвертер, в нём не дублируются: имя кнопки операции, `очиститьФорму`,
`заголовокФормы`, `перезагрузить`, а также настройки поля-штрихкода
(`кнопкаОчистки`, `автофокус`, `режимСканирования`,
`значенияПриемниковПоУмолчанию`) появляются в IR автоматически.

Базовый адрес сервера задаётся в шапке формы, а методы — относительными путями:

```yarbp
форма .заголовокФормы Отправка данных в 1С
  .сервис http://127.0.0.1:8765/rt_morato_bot/hs/dp

  операция = Подобрать товар / a1
    ...
      .хук /link
  операция = Отправить результат / a2
    .урл /processing
```

Движок сам склеивает `/link` → `http://…/rt_morato_bot/hs/dp/link` и
`/processing` → `http://…/rt_morato_bot/hs/dp/processing`. Полный URL в
`.хук`/`.урл` остаётся полным. Если `.сервис` нет, относительные пути работают
как раньше — от origin страницы. Адрес сервера выводится отдельной строкой в
шапке ТСД.

Таблица описывается поколоночно, а не пореквизитно:

```yarbp
таблица = Товары в заказе / a2_t1
  .редактируемая да
  :
    .имя Товар
    .измерение да
    .приемник:Справочник.Номенклатура = Номенклатура
  :
    .имя Кол‑во
    .приемник:Число(15,3) = Количество
```

Колонка — анонимный объект после `:`. Если `.измерение` не указано, числовой
тип приёмника даёт ресурс, остальные типы — измерение. Открыть: «Примеры» →
«Форма ТСД». Файл встроенный (`isBuiltin`): его нельзя переименовать или
затереть. Свои правки — через «Создать файл».

`Кол‑во` в образце написано с **неразрывным дефисом U+2011**, а не с `-`: так
поле таблицы сопоставляется с ресурсом. Замена символа на обычный дефис ломает
сопоставление, поэтому текст примера сверяется с первоисточником в тестах
(включая отдельную проверку U+2011).

## Мок-сервер

Кнопка «мок-сервер» скачивает `flexforms_mock_server.py` — один модуль на
стандартной библиотеке Python 3. По умолчанию он слушает `127.0.0.1:8765` и
повторяет контракты движка:

| метод | адрес | назначение |
| --- | --- | --- |
| `POST` | `<любой префикс>/link/` | хук штрихкода; отвечает `message.requested_fields` с `id`, `name`, `uid` |
| `POST` | `<любой префикс>/processing` | принимает `{fields, table}` и возвращает подтверждение |
| `GET` | `<любой префикс>/ping` | health для индикатора сети |

Метод определяется по **последнему сегменту** пути, поэтому `rt_morato_bot`
и `hs/dp` — не обязательный префикс, а просто пример публикации 1С. Мок
ответит и на `/api/v2/link`, и на `/custom/processing`, и на короткие
`/link`, `/processing`, `/ping`, `/health`. Это позволяет форме задать
`.сервис http://host/api/v2` и относительные `.хук /link`, `.урл /processing`.

CORS (включая `OPTIONS`) нужен, чтобы форма работала с `file://` и с другого
порта. `OPTIONS` — это preflight CORS, который браузер отправляет перед
cross-origin POST; тела и обработки данных в нём нет, POST после него приходит
отдельно. Запуск: `python flexforms_mock_server.py`.

При запуске двойным кликом окно не закрывается молча: если порт занят
(например, мок уже запущен в IDLE или вторым окном), скрипт показывает
понятное сообщение и ждёт Enter. Первый экземпляр продолжает работать;
для второго можно закрыть старый процесс или указать `--port 8766`.

Адрес сервера (`сервис`) хранится в шапке формы и показывается в верхней
строке ТСД. Если `.хук` или `.урл` задан без протокола (`/link`,
`/processing`), движок приклеивает его к `сервису`; полный URL используется
как есть, а без `сервиса` относительный путь остаётся относительным.

## Сгенерированные ассеты

Файлы `FlexFormsStyles.js`, `FlexFormsRuntime.js`, `FlexFormsMarkup.js` и
`FlexFormsMockServer.js` руками не правятся — они собираются из первоисточников
и проверяются тестом:

```bash
python yarbp/tools/build-flexforms-assets.py           # перегенерировать
python yarbp/tools/build-flexforms-assets.py --check   # сверить (это делает и тест)
```

Источники: `редизайн/kb8-inventory-redesign.html` (CSS, оболочка, движок) и
`flex-forms-legacy/constructor.html` (`getSVG()` — рисунок корпуса 346×758 по
viewBox 208×457). Прямоугольник экрана в рисунке задан в самом генераторе
(`SCREEN_IN_FRAME`): 338×447 со сдвигом 4/80. Отдельной области под экран в
рисунке нет — есть только шапка 1С-клиента (кончается на y=64.9) и клавиатура
(начинается на y=535.6), поэтому прямоугольник подобран по ним: по 4 точки
корпуса с боков, 15 точек до трёх точек меню, 8.6 до клавиатуры (такой же зазор,
как между её кнопками — 5 точек рисунка). Странице формы нужна высота 471
(`PREVIEW_FORM`: ниже 471 обрезается нижняя панель), ширина — 356.

Дальше рамка **увеличивается** под страницу, а не страница уменьшается под
рамку: 346 × 356/338 = 364 и 758 × 471/447 = 799, а экран в ней становится ровно
356×471 со сдвигом 4/84. Так iframe не масштабируется вовсе — 1 CSS px формы
равен 1 px рамки, — и в предпросмотре форма выглядит точка в точку так же, как в
редизайне. Обратный вариант (iframe 356×471, уменьшенный в 0.949 под экран
338×447) давал лишний пересэмплинг: текст и 1px-рамки полей мылились, а вместе с
подгонкой корпуса под панель форма выходила примерно на 14 % мельче редизайна.
Углы экрана не скругляются. Легаси-числа `renderMockup()` (308×400 со сдвигом
3/80) подбирались под старую вёрстку формы и с рисунком не совпадали, поэтому их
не используем.

Почему строки, а не отдельные `.css`/`.js`: страница предпросмотра — один
самодостаточный файл без сети (он уходит в `srcdoc` iframe), а редактор
открывается по `file://`. Прочитать соседний файл и подставить его в
`<script>`/`<style>` в этих условиях нельзя, поэтому исходники лежат в
ES-модулях массивами строк (`[...].join('\n')`).

## Осознанные отличия от легаси-конструктора

1. **Таблица.** В `flex-forms-legacy/constructor.html` у `renderTable` были
   строка итога (`getFooter`: `итог`, `итогЗаголовок`, `итогЗначение`, `колонок`)
   и строка-заготовка для редактируемых таблиц (`getAnEmptyRow`). В редизайне
   их нет, а перенос держит паритет с редизайном побайтово — поэтому итогов и
   пустой строки в предпросмотре тоже нет. Нужны — сначала в дизайн
   (`kb8-inventory-redesign.html`), затем перегенерация ассетов.
2. **Предпросмотр: снимок localStorage и автофокус.** Движок при загрузке
   восстанавливает из `localStorage` не только значения полей, но и сам IR.
   В редакторе IR каждый раз новый, поэтому `buildFormPage(ir, { preview: true })`
   вставляет перед движком короткий скрипт: IR из снимка выбрасывается, значения
   полей и `uid` остаются (они привязаны к `ид` и переживают правку разметки).
   Второй скрипт — после движка: он подменяет `setFocus()` пустышкой. Движок
   после каждой отрисовки ставит курсор в поле с маркером `.autofocus-mark`
   (а если такого нет — в выбор операции): на ТСД это жизненно нужно сканеру,
   а в редакторе фокус уходит из окна кода — набирать разметку невозможно,
   потому что предпросмотр перерисовывается на каждую правку. Маркер в разметке
   остаётся, гасится только вызов. В странице без предпросмотра (её собирает
   расширение 1С, и её же сверяет паритет-тест) обоих скриптов нет — она ведёт
   себя как исходная страница редизайна, с автофокусом.
3. **Рамка.** `getSVG()` перенесён символ-в-символ. Отдельной области под экран
   в рисунке нет, поэтому место экрана подобрано по нарисованным шапке
   1С-клиента (кончается на y=64.9) и клавиатуре (начинается на y=535.6):
   338×447 со сдвигом 4/80 в координатах рисунка 346×758 — по 4 точки корпуса с
   боков, 15 точек до трёх точек меню, 8.6 до клавиатуры (такой же зазор, как
   между кнопками), углы не скруглены (легаси-раскладка `#ui-mock-container`
   308×400 со сдвигом 3/80 с рисунком не совпадала и обрезала форму справа и
   снизу). Странице формы нужна высота 471 — при меньшей обрезается её нижняя
   панель с кнопкой, — поэтому рамка увеличивается до 364×799 так, чтобы
   нарисованный экран стал ровно 356×471: iframe верстается в этом логическом
   размере и **не масштабируется** (никакого `transform: scale()` внутри экрана),
   а не пересобирается под экран. Рамку целиком подгоняет под панель рендерер
   (`transform: scale()` на `.ff-phone`, размер раскладки задаёт обёртка
   `.ff-phone-scale`), причём **не крупнее 1:1**: масштаб 1 — это ровно тот же
   размер, что на ТСД, поэтому предпросмотр не врёт ни о размере, ни о резкости.
   По высоте он вписывает не корпус, а саму форму (запас до низа экрана), иначе
   нарисованная клавиатура (799 против 84+471) ужимала бы форму даже в высокой
   панели — это и была та самая разница «на 15 %» с редизайном; хвост корпуса
   уезжает в прокрутку панели.
4. **Кнопка выгрузки.** В панели предпросмотра одна кнопка — `JSON`
   (`.ff-export-btn--config`): скачивается `<заголовок формы>.json` в UTF-8 без
   BOM, текст — ровно тот, что страница получает в `<data id="form-params">`.
   Подпись вместо иконки по двум причинам: `static/download-*.svg` объявлена
   как 800×800 и без ограничения растягивала кнопку на всю панель, а
   одинаковая иконка не объясняла, что скачивается именно JSON. Если IR неполный
   (нет `type` или `children`), файл не пишется — под кнопкой на 4 секунды
   появляется плашка с причиной.
5. **Панель редактора.** Предпросмотр живёт в `.ui-render-container` панели
   результата (тот же контракт, что у остальных рендереров): редактор результата
   скрывается, при смене флейвора контейнер удаляется.
6. **Типографика и плотность под ТСД.** Шрифты страницы дважды уменьшены на 1 px
   относительно первого варианта редизайна: базовый 15/1.45, подписи полей 11,
   значения 17, кнопка 15. Зазоры поджаты: `.grid-box` — `row-gap: 6px`,
   `.screen` — `gap: 7px`, `.card` — `padding: 7px 9px`, `.pager` —
   `margin-top: 8px`, `.check-row` — `padding: 5px 2px`.
   Высота поля теперь одна на все поля — переменная `--field-h: 33px`: раньше
   высоту числового поля задавал не текст, а кнопки каунтера −/+ (40 px), и
   «Кол-во» было на 9 точек выше строчных полей. Кнопки каунтера подгоняются под
   переменную (`height: calc(var(--field-h) - 6px)`), зелёная кнопка действия —
   42 px вместо 46 (на экране 356 точек 46 читалась как отдельная панель).
   Измерено в iframe 356×471: `.control` и `.qty-input-wrap` — 33.00,
   `.btn` — 42.00, «Добавить в заказ» заканчивается на 399.7 px.
   Правится только в редизайне — в редактор приезжает перегенерацией ассетов.
7. **Системный спиннер числового поля.** `all:unset` в полях снимает
   `appearance` у самого `<input>`, но у псевдоэлементов движка
   `::-webkit-inner-spin-button` / `::-webkit-outer-spin-button` `appearance`
   свой — поэтому стрелки всплывали по наведению поверх нашего каунтера −/+.
   В редизайне `appearance: none` задан и контролу (плюс `textfield` для
   Firefox), и обоим псевдоэлементам. На `display: none` не полагаемся: в
   Chromium на этих псевдоэлементах он не применяется (computed `display`
   остаётся `inline-block`), стрелки убирает именно `appearance` — проверено
   пробой и закреплено проверкой в `tests/flexforms/smoke.html`.
8. **Служебные кнопки — в потоке.** Тема, клавиатура и сброс раньше были
   вертикальным `position: fixed` стеком справа снизу: на экране 356×471 он
   перекрывал «Характеристику», «Кол-во» и кнопку действия. Теперь это обычная
   строка `.tools-row` под `.pager` с `justify-content: flex-end` — кнопки не
   перекрывают интерфейс и не «плавают» при прокрутке экранов. Тост при этом
   прячется по-настоящему (`opacity: 0; visibility: hidden`): одного
   `translateY(120%)` не хватало — верхние ~20 точек тоста оставались видны
   белой полоской внизу экрана.

## Тесты

```bash
python yarbp/tests/flexforms/run_tests.py               # всё, включая браузер
python yarbp/tests/flexforms/run_tests.py --no-browser  # только логика (quickjs)
```

Проверяется: дословность ассетов, `ast.json → target.json` (побайтово), паритет
собранной страницы с `kb8-inventory-redesign.html` (побайтово), отличие страницы
без предпросмотра от предпросмотра ровно на два блока предпросмотра (сброс
снимка и заглушка автофокуса), геометрия рамки, конфиг для 1С (текст = `<data>`
страницы, имя `<заголовок>.json`, отказ на неполном IR), подсказки,
компактность примера «Форма ТСД» и дымовой прогон в
Chrome (регистрация флейвора, монтирование предпросмотра **этим примером**, работу
движка внутри iframe, пропуск перерисовки при неизменном IR, а также совпадение
IR примера с `builtin-ir.json`). В том же прогоне проверяется поведение,
которое как раз и разъезжалось при ручном переносе: режим «клавиатура
выключена» (`readOnly` + `inputmode="none"` и ввод через мост сканера),
отсутствие типового спиннера `input[type=number]` (`appearance: none` и у поля,
и у его `::-webkit-inner/outer-spin-button`), свайп
с анимацией трека (`translateX`), сохранение выбранной темы после перерисовки
iframe, кнопки «JSON»/«HTML»/«мок-сервер» (скачиваются `.json`, `.html` и `.py`), а также
автофокус: в предпросмотре он не срабатывает (правка рендера),
а в собранной для ТСД странице — срабатывает (контрольная проверка
в том же прогоне, иначе первая ничего не доказывала бы).
