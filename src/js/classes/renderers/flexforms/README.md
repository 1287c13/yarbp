# Флейвор «форма-ТСД»

`! как форма-тсд` — предпросмотр формы ТСД в рамке корпуса терминала и выгрузка
конфига JSON, который расширение 1С подставляет в оболочку ТСД вместо
`<data id="form-params">`.

Синонимы директивы (после `normalizeFlavorName`: без `-`, `_`, пробелов, нижний
регистр): `как тсд`, `as flexforms`, `как сканер`.

## Поток данных

```
разметка ЯРБП
   │  YarbpLexer + YarbpParser
   ▼
AST
   │  ast-converters/FlexFormsConvertor.js  (YarbpFlexFormsConverter)
   ▼
IR формы (JSON — тот же формат, что читает движок ТСД)
   │  flexforms/FlexFormsPage.js
   ├─ buildFormPage   ──►  HTML-страница  ──►  iframe[srcdoc] в рамке ТСД  (предпросмотр)
   ├─ buildFormConfig ──►  <заголовок>.json  ──►  файл для 1С              (кнопка «JSON»)
   └─ flexforms_mock_server.py ──► локальный сервер ──► хук / отправка / health (кнопка «мок-сервер»)
```

Страница формы — встроенная копия эталонной страницы ТСД: тот же CSS, тот же
движок (хук ШК, приёмники, таблицы, отправка, флаги, тема, клавиатура,
индикатор сети). В движок добавлены `.сервис` (склейка относительных адресов и
строка сервера в шапке) и ключ доступа кэш-сервиса (заголовок `X-Api-Key`,
`Idempotency-Key` у отправки, `401` → страница входа — см. раздел «Кэш-сервис»).
Отличия остального — про подстановку: в
`<data id="form-params">` лежит IR, собранный из разметки редактора, а не
форма-образец, а в предпросмотре к странице добавлены два коротких скрипта
(снимок `localStorage` и автофокус — см. п. 2 ниже).

Страница нужна только предпросмотру. Наружу редактор отдаёт **не её, а конфиг
JSON**: самодостаточную страницу для ТСД собирает расширение 1С, подставляя
конфиг в оболочку вместо `<data id="form-params">`. Поэтому текст конфига и
текст, который получает предпросмотр, — один и тот же (`serializeFormIR`).

## Контракт конфига с расширением 1С

Выгрузка «JSON» — это конфиг для расширения FlexFormsTech (`фф_КонфигТСД`).
Полное описание контракта со стороны 1С — `kpp/docs/11-tsd-config.md`; здесь —
что именно пишет конструктор.

| Ключ корня | Разметка ЯРБП | Обязателен | Смысл |
| --- | --- | --- | --- |
| `type` | `форма` | да | вид узла: `форма` |
| `заголовокФормы` | `.заголовокФормы` | да | заголовок в шапке ТСД |
| `сервис` | `.сервис` | нет | базовый адрес; относительные `.хук`/`.урл` склеиваются с ним. Кэш-сервис подменяет его своим при выдаче |
| `типКлиента` | `.типКлиента` | да | тип публикации клиента (`ПодборТовара`); без него 1С берёт тип по умолчанию |
| `версияКонфига` | `.версияКонфига` | нет | авторская версия конфига (миграции в 1С) |
| `подписки` | `..подписки Справочник.Имя …` | нет | объекты, на которые 1С ставит подписку обновления кэша |
| `обработчики` | `:обработчики` | нет | коды обработчиков: `формированиеКэша[]` и `сообщения[]` |
| `children` | операции/поля/таблицы | да | состав формы (вне контракта конфига) |

Строка обработчика — объект без `type`:

```json
{
  "обработчики": {
    "формированиеКэша": [{ "имяТипа": "Справочник.Номенклатура", "код": "…", "язык": "bsl" }],
    "сообщения": [{ "типСообщения": "ПодборТовара", "код": "…", "язык": "bsl" }]
  }
}
```

Правила, которые держит конвертер (`FlexFormsConvertor.js`):

1. `обработчики` — **свойство корня**, а не узел `children` (`OBJECT_PROPS`);
   ключ `type` внутри него не пишется.
2. Фрагмент кода (` ```bsl … ``` `) приезжает парой `код` + `язык`; язык в
   нижнем регистре, без языка — `bsl`. Пустой код остаётся в конфиге: об этом
   предупреждает уже 1С.
3. `типКлиента`, `версияКонфига`, `подписки` — обычные свойства формы, конвертер
   пропускает их как есть (тип значения задаёт разметка: `..подписки` — массив).
4. `хэш`, `автор`, `дата`, `Отправитель` не выгружаются: хэш 1С не читает,
   отправителя подставляет сама при разборе сообщения.
5. `auth` в конфиге не выгружается: ключ доступа не едет вместе с формой
   (см. следующий раздел).

Перед сохранением файла `formConfigWarnings` показывает неблокирующие
замечания (нет `типКлиента`, пустой `код`, `подписки` без вида объекта): конфиг
применится, но на приёмке это стоит увидеть. Структурные ошибки (`type`,
`children`) по-прежнему блокируют выгрузку (`formConfigError`).

## Кэш-сервис: ключ доступа, хук и отправка

Страницу выдаёт кэш-сервис (`GET /v1/clients/latest?type=…`), он же подменяет
`сервис` своим адресом. Ключ доступа в тексте формы не лежит (ADR-13):

1. общая страница входа `/v1/clients/auth?type=<типКлиента>` проверяет ключ
   (`POST /v1/auth/verify`) и кладёт его в `localStorage` под именем `ff_token`;
2. форма открывается как `/v1/clients/latest?key=<ключ>` — движок забирает
   ключ из адреса, сохраняет в `ff_token` и **убирает из адресной строки**;
3. каждый запрос к сервису уходит с заголовком `X-Api-Key` (хук, отправка,
   пинг); `401` означает «ключ не принят» — форма снимает ключ и уходит на
   страницу входа с тем же `типКлиента`. Адрес входа — от **корня хоста, который
   отдал страницу** (`/v1/clients/auth`), а не от `сервис`: `сервис` — это адрес
   1С-шлюза (`http://host/rt_m_bot/hs/dp`), и склейка увела бы на
   `/rt_m_bot/hs/dp/v1/clients/auth` (404 вместо страницы входа);
4. отправка дополнительно несёт `Idempotency-Key` — короткий хэш тела
   (`<ид операции>-<8 hex>`): повтор после обрыва связи не создает второй
   документ в 1С (ADR-14);
5. если ключа `сервис` в конфиге не было, адрес берётся из
   `window.FLEX_FORMS_TECH`, который подставляет кэш-сервис.

Без ключа всё работает как раньше (стенд 1С, мок-сервер, редактор): заголовок
не пишется, `401` не наступает, редиректа нет. В предпросмотре редактора
(`about:srcdoc` в iframe) и при открытии страницы файлом (`file:`) перехода на
вход тоже нет — там нет ни сервиса, ни страницы входа, поэтому `401` остаётся
ошибкой отправки. Проверяется живьём — `tests/flexforms/auth-contract.html`
+ заглушка `tests/flexforms/auth_server.py`.

Что осталось на стороне кэш-сервиса и расширения 1С (оболочка страницы,
`_AUTH_SHIM`, редирект на вход) — `TASKS-CACHE-SERVICE.md` в этой папке.

## Пример в редакторе

В папке «Примеры» редактора есть файл **«Форма ТСД»** (`FileManager`,
`builtin-9`) — компактный пример актуальной разметки. Значения, которые
подставляет конвертер, в нём не дублируются: имя кнопки операции,
`очиститьФорму`, `отображатьСтатистику`, `заголовокФормы`, а также настройки
поля-штрихкода (`кнопкаОчистки`, `автофокус`, `режимСканирования`,
`значенияПриемниковПоУмолчанию`) появляются в IR автоматически.

Базовый адрес сервера задаётся в шапке формы, а методы — относительными путями:

```yarbp
форма .заголовокФормы Отправка данных в 1С
  .сервис http://127.0.0.1:8765/rt_m_bot/hs/dp

  операция = Подобрать товар / a1
    ...
      .хук /link
  операция = Отправить результат / a2
    .урл /processing
```

Движок сам склеивает `/link` → `http://…/rt_m_bot/hs/dp/link` и
`/processing` → `http://…/rt_m_bot/hs/dp/processing`. Полный URL в
`.хук`/`.урл` остаётся полным. Если `.сервис` нет, относительные пути работают
как раньше — от origin страницы. Адрес сервера выводится отдельной строкой в
шапке ТСД.

Таблица описывается поколоночно, а не пореквизитно:

```yarbp
таблица = Товары в заказе / a2_t1
  .редактируемая да
  :
    .имя Товар
    .измерение да
    .приемник:Справочник.Номенклатура = Номенклатура
  :
    .имя Кол‑во
    .приемник:Число(15,3) = Количество
```

Колонка — анонимный объект после `:`. Если `.измерение` не указано, числовой
тип приёмника даёт ресурс, остальные типы — измерение. Открыть: «Примеры» →
«Форма ТСД». Файл встроенный (`isBuiltin`): его нельзя переименовать или
затереть. Свои правки — через «Создать файл».

`Кол‑во` в образце написано с **неразрывным дефисом U+2011**, а не с `-`: так
поле таблицы сопоставляется с ресурсом. Замена символа на обычный дефис ломает
сопоставление, поэтому текст примера сверяется с первоисточником в тестах
(включая отдельную проверку U+2011).

## Сброс данных после действия и табло статистики

Два флага операции управляют тем, что происходит ПОСЛЕ нажатия кнопки.

**`.урл` — действие с внешним приёмником.** Если `.урл` не пуст и в разметке
действия нет явного `.перезагрузить нет`, то после **успешной** отправки данные
приложения сбрасываются целиком: поля всех экранов, таблицы-приёмники, снимок
`tsd-form-state`, и форма встаёт на первый экран. Иначе оператор отправит ту же
партию второй раз. `перезагрузить` в IR по умолчанию **не пишется** (отсутствие
ключа — это и есть умолчание), а `.перезагрузить нет` приезжает как `false` и
означает осознанный отказ: данные остаются в форме (например, для повторной
досылки). Раньше здесь подставлялось `false` всем операциям, поэтому отличить
«нет» от «не указано» было нельзя, и сброс зависел только от `очиститьФорму`.

Если отправка не удалась, данные не стираются молча: движок спрашивает
«Отправка не удалась, очистить форму?». Действия без `.урл` (например,
«Подобрать товар») по-прежнему очищают только свой экран по `очиститьФорму`.

**`.отображатьСтатистику` — табло «Позиций / Кол-во / Статус»** над карточкой
полей. По умолчанию включено (в IR — `true`), `.отображатьСтатистику нет` —
`false`. Показывается оно всё равно **только у действий с непустым `.урл`**: это
сводка того, что уйдёт на сервер, поэтому у локальных действий (только `хук` или
приёмник) табло не выводится, даже если таблица есть. Значения табло считаются
только из строк таблицы-приёмника, «Статус» — по `..проверятьЗаполнение`
операции; после сброса табло пересчитывается из очищенного IR (раньше оно
оставалось с цифрами отправленной партии, потому что обновлялось из старой
модели `state.params`).

```yarbp
операция = Отправить результат / a2
  .урл /processing            # действие с внешним приёмником: сброс после успеха
  .отображатьСтатистику да    # табло Позиций/Кол-во/Статус (и так по умолчанию)
```

```yarbp
операция = Дослать повторно / a3
  .урл /processing
  .перезагрузить нет          # явный отказ от сброса: данные остаются в форме
```

## Мок-сервер

Кнопка «мок-сервер» скачивает `flexforms_mock_server.py` — один модуль на
стандартной библиотеке Python 3. По умолчанию он слушает `127.0.0.1:8765` и
повторяет контракты движка:

| метод | адрес | назначение |
| --- | --- | --- |
| `POST` | `<любой префикс>/link/` | хук штрихкода; отвечает `message.requested_fields` с `id`, `name`, `uid` |
| `POST` | `<любой префикс>/processing` | принимает `{fields, table}` и возвращает подтверждение |
| `GET` | `<любой префикс>/ping` | health для индикатора сети |

Метод определяется по **последнему сегменту** пути, поэтому `rt_morato_bot`
и `hs/dp` — не обязательный префикс, а просто пример публикации 1С. Мок
ответит и на `/api/v2/link`, и на `/custom/processing`, и на короткие
`/link`, `/processing`, `/ping`, `/health`. Это позволяет форме задать
`.сервис http://host/api/v2` и относительные `.хук /link`, `.урл /processing`.

CORS (включая `OPTIONS`) нужен, чтобы форма работала с `file://` и с другого
порта. `OPTIONS` — это preflight CORS, который браузер отправляет перед
cross-origin POST; тела и обработки данных в нём нет, POST после него приходит
отдельно. Запуск: `python flexforms_mock_server.py`.

При запуске двойным кликом окно не закрывается молча: если порт занят
(например, мок уже запущен в IDLE или вторым окном), скрипт показывает
понятное сообщение и ждёт Enter. Первый экземпляр продолжает работать;
для второго можно закрыть старый процесс или указать `--port 8766`.

Адрес сервера (`сервис`) хранится в шапке формы и показывается в верхней
строке ТСД. Если `.хук` или `.урл` задан без протокола (`/link`,
`/processing`), движок приклеивает его к `сервису`; полный URL используется
как есть, а без `сервиса` относительный путь остаётся относительным.

## Встроенные ассеты

Файлы `FlexFormsStyles.js`, `FlexFormsRuntime.js`, `FlexFormsMarkup.js` и
`FlexFormsMockServer.js` — встроенные копии страницы и мока. Внешнего
генератора, каталога `редизайн/` и других источников вне репозитория нет:
проект и тесты работают только с тем, что лежит в репозитории. Править их можно
напрямую, но это меняет предпросмотр; браузерный дым проверит, что страница и IR
не разъехались.

Рамка **увеличивается** под страницу, а не страница уменьшается под рамку:
346 × 356/338 = 364 и 758 × 471/447 = 799, а экран в ней становится ровно
356×471 со сдвигом 4/84. Так iframe не масштабируется вовсе — 1 CSS px формы
равен 1 px рамки. Обратный вариант (iframe 356×471, уменьшенный в 0.949 под
экран 338×447) давал лишний пересэмплинг: текст и 1px-рамки полей мылились.
Углы экрана не скругляются.

Почему строки, а не отдельные `.css`/`.js`: страница предпросмотра — один
самодостаточный файл без сети (он уходит в `srcdoc` iframe), а редактор
открывается по `file://`. Прочитать соседний файл и подставить его в
`<script>`/`<style>` в этих условиях нельзя, поэтому исходники лежат в
ES-модулях массивами строк (`[...].join('\n')`).

## Правки поверх встроенной копии

Файлы `FlexFormsRuntime.js`, `FlexFormsStyles.js` и `FlexFormsMockServer.js`
содержат точечные правки безопасности. Отдельной перегенерации нет — правки
живут прямо в этих файлах:

| Место | Что сделано | Зачем |
| --- | --- | --- |
| `readParams`/`writeParams` | читают и пишут IR только через `textContent` (через `getParams`/`setParams`) | `innerHTML` превращал `<`/`&` из значений в разметку: данные портились, тег в подписи исполнялся (D-01) |
| `renderStandardField` | `id` и `имя` вынесены в `idAttr`/`nameSafe` = `escapeAttr(...)` | `id="${id}"` и `${fieldParams['имя']}` давали инъекцию в атрибут и в текст (D-02) |
| `renderSelectField` | то же плюс экранирование `option['значение']`/`option['имя']` | там были все четыре сырых подстановки |
| `renderCheckboxField` | то же для `id` и `имя` | — |

Правки помечены в исходнике комментариями `ЯРБП-ПРАВКА (D-xx)`, чтобы их было
видно при чтении. Тест `tests/security/run_tests.py` проверяет, что сырых
подстановок не осталось.

## Осознанные отличия от легаси-конструктора

1. **Таблица.** В легаси-конструкторе у `renderTable` были
   строка итога (`getFooter`: `итог`, `итогЗаголовок`, `итогЗначение`, `колонок`)
   и строка-заготовка для редактируемых таблиц (`getAnEmptyRow`). Итогов в
   эталонной странице по-прежнему нет, а **добавление строк есть** — своим
   способом: кнопка `.row-add` (`addTableRow`) пишет пустую строку в IR, а не
   рисует `tr`-заготовку в DOM; правка ячеек тоже уезжает в IR
   (`syncTableCell`). Встроенная копия страницы — единственный источник;
   отдельной перегенерации из внешнего дизайна нет.
2. **Предпросмотр: снимок localStorage и автофокус.** Движок при загрузке
   восстанавливает из `localStorage` не только значения полей, но и сам IR.
   В редакторе IR каждый раз новый, поэтому `buildFormPage(ir, { preview: true })`
   вставляет перед движком короткий скрипт: IR из снимка выбрасывается, значения
   полей и `uid` остаются (они привязаны к `ид` и переживают правку разметки).
   Второй скрипт — после движка: он подменяет `setFocus()` пустышкой. Движок
   после каждой отрисовки ставит курсор в поле с маркером `.autofocus-mark`
   (а если такого нет — в выбор операции): на ТСД это жизненно нужно сканеру,
   а в редакторе фокус уходит из окна кода — набирать разметку невозможно,
   потому что предпросмотр перерисовывается на каждую правку. Маркер в разметке
   остаётся, гасится только вызов. В странице без предпросмотра (её собирает
   расширение 1С, и её же проверяет браузерный дым) обоих скриптов нет — она
   ведёт себя как эталонная страница, с автофокусом.
3. **Рамка.** `getSVG()` перенесён символ-в-символ. Отдельной области под экран
   в рисунке нет, поэтому место экрана подобрано по нарисованным шапке
   1С-клиента (кончается на y=64.9) и клавиатуре (начинается на y=535.6):
   338×447 со сдвигом 4/80 в координатах рисунка 346×758 — по 4 точки корпуса с
   боков, 15 точек до трёх точек меню, 8.6 до клавиатуры (такой же зазор, как
   между кнопками), углы не скруглены (легаси-раскладка `#ui-mock-container`
   308×400 со сдвигом 3/80 с рисунком не совпадала и обрезала форму справа и
   снизу). Странице формы нужна высота 471 — при меньшей обрезается её нижняя
   панель с кнопкой, — поэтому рамка увеличивается до 364×799 так, чтобы
   нарисованный экран стал ровно 356×471: iframe верстается в этом логическом
   размере и **не масштабируется** (никакого `transform: scale()` внутри экрана),
   а не пересобирается под экран. Рамку целиком подгоняет под панель рендерер
   (`transform: scale()` на `.ff-phone`, размер раскладки задаёт обёртка
   `.ff-phone-scale`), причём **не крупнее 1:1**: масштаб 1 — это ровно тот же
   размер, что на ТСД, поэтому предпросмотр не врёт ни о размере, ни о резкости.
   По высоте он вписывает не корпус, а саму форму (запас до низа экрана), иначе
   нарисованная клавиатура (799 против 84+471) ужимала бы форму даже в высокой
   панели — это и была та самая разница «на 15 %» с эталонной страницей; хвост корпуса
   уезжает в прокрутку панели.
4. **Кнопка выгрузки.** В панели предпросмотра одна кнопка — `JSON`
   (`.ff-export-btn--config`): скачивается `<заголовок формы>.json` в UTF-8 без
   BOM, текст — ровно тот, что страница получает в `<data id="form-params">`.
   Подпись вместо иконки по двум причинам: `static/download-*.svg` объявлена
   как 800×800 и без ограничения растягивала кнопку на всю панель, а
   одинаковая иконка не объясняла, что скачивается именно JSON. Если IR неполный
   (нет `type` или `children`), файл не пишется — под кнопкой на 4 секунды
   появляется плашка с причиной.
5. **Панель редактора.** Предпросмотр живёт в `.ui-render-container` панели
   результата (тот же контракт, что у остальных рендереров): редактор результата
   скрывается, при смене флейвора контейнер удаляется.
6. **Типографика и плотность под ТСД.** Шрифты страницы дважды уменьшены на 1 px
   относительно первого варианта эталонной страницы: базовый 15/1.45, подписи полей 11,
   значения 17, кнопка 15. Зазоры поджаты: `.grid-box` — `row-gap: 6px`,
   `.screen` — `gap: 7px`, `.card` — `padding: 7px 9px`, `.pager` —
   `margin-top: 8px`, `.check-row` — `padding: 5px 2px`.
   Высота поля теперь одна на все поля — переменная `--field-h: 33px`: раньше
   высоту числового поля задавал не текст, а кнопки каунтера −/+ (40 px), и
   «Кол-во» было на 9 точек выше строчных полей. Кнопки каунтера подгоняются под
   переменную (`height: calc(var(--field-h) - 6px)`), зелёная кнопка действия —
   42 px вместо 46 (на экране 356 точек 46 читалась как отдельная панель).
   Измерено в iframe 356×471: `.control` и `.qty-input-wrap` — 33.00,
   `.btn` — 42.00, «Добавить в заказ» заканчивается на 399.7 px.
   Правится только во встроенной копии страницы; отдельной перегенерации нет.
7. **Системный спиннер числового поля.** `all:unset` в полях снимает
   `appearance` у самого `<input>`, но у псевдоэлементов движка
   `::-webkit-inner-spin-button` / `::-webkit-outer-spin-button` `appearance`
   свой — поэтому стрелки всплывали по наведению поверх нашего каунтера −/+.
   В эталонной странице `appearance: none` задан и контролу (плюс `textfield` для
   Firefox), и обоим псевдоэлементам. На `display: none` не полагаемся: в
   Chromium на этих псевдоэлементах он не применяется (computed `display`
   остаётся `inline-block`), стрелки убирает именно `appearance` — проверено
   пробой и закреплено проверкой в `tests/flexforms/smoke.html`.
8. **Служебные кнопки — в потоке.** Тема, клавиатура и сброс раньше были
   вертикальным `position: fixed` стеком справа снизу: на экране 356×471 он
   перекрывал «Характеристику», «Кол-во» и кнопку действия. Теперь это обычная
   строка `.tools-row` с `justify-content: flex-end` **после формы**, `position`
   у неё `static` (никаких `fixed`/`sticky`), и она не резервирует высоту:
   прокручивается весь каркас (`.app { overflow-y: auto }`), а `.pager` получает
   высоту по содержимому экрана (`flex: 1 0 auto`, у `.track`/`.screen` больше
   нет `height: 100%`). Если места хватает — строка прижата к низу (растёт
   `.pager`), если форме места не хватает — строка уезжает за нижнюю границу и
   НЕ сжимает поля и кнопку действия. Тост при этом прячется по-настоящему
   (`opacity: 0; visibility: hidden`): одного `translateY(120%)` не хватало —
   верхние ~20 точек тоста оставались видны белой полоской внизу экрана.

## Тесты

```bash
python yarbp/tests/flexforms/run_tests.py               # пример + браузерный дым
python yarbp/tests/flexforms/run_tests.py --no-browser  # только пример
```

Проверяется: компактность встроенного примера «Форма ТСД» в `FileManager` и
дымовой прогон в Chrome/Edge (регистрация флейвора, монтирование предпросмотра
этим примером, работа движка внутри iframe, совпадение IR примера с
`builtin-ir.json`). Отдельный прогон — контракт с кэш-сервисом
(`auth-contract.html` + заглушка `auth_server.py`, 23 проверки): ключ из `?key=` в
`localStorage`, заголовок `X-Api-Key` у хука и отправки, `Idempotency-Key`,
склейка `сервис` + относительный `.хук`, preflight CORS, `401` → страница входа
по корню хоста (а не по адресу 1С-шлюза), снятие негодного ключа. В том же
прогоне — поведение формы: `readOnly` + мост
сканера, отсутствие спиннера, свайп, тема, кнопки «JSON»/«HTML»/«мок-сервер»,
автофокус, сброс после отправки, таблицы и служебные кнопки.

Внешних зависимостей нет: только стандартная библиотека Python и браузер.
