# Флейвор «форма-ТСД»

`! как форма-тсд` — предпросмотр формы ТСД в рамке корпуса терминала и экспорт
самодостаточной HTML-страницы (её кладут на ТСД рядом с 1С-клиентом).

Синонимы директивы (после `normalizeFlavorName`: без `-`, `_`, пробелов, нижний
регистр): `как тсд`, `as flexforms`, `как сканер`.

## Поток данных

```
разметка ЯРБП
   │  YarbpLexer + YarbpParser
   ▼
AST
   │  ast-converters/FlexFormsConvertor.js  (YarbpFlexFormsConverter)
   ▼
IR формы (JSON — тот же формат, что читает движок ТСД)
   │  flexforms/FlexFormsPage.js  (buildFormPage)
   ▼
HTML-страница формы  ──►  iframe[srcdoc] в рамке ТСД   (предпросмотр)
                     └─►  файл для ТСД                  (кнопка «Скачать HTML»)
```

Страница формы — это **дословно** `редизайн/kb8-inventory-redesign.html`:
тот же CSS, тот же движок (хук ШК, приёмники, таблицы, отправка, флаги, тема,
клавиатура, индикатор сети). Отличие одно: в `<data id="form-params">` лежит IR,
собранный из разметки редактора, а не форма-образец.

## Пример в редакторе

В папке «Примеры» редактора есть файл **«Форма ТСД»** (`FileManager`,
`builtin-9`) — это дословно первый блок разметки из
`редизайн/задача-замена-целевого-формата/образцы разметки.md`: тот самый, из
которого получены `ast.json`, `target.json` и HTML редизайна. Отличие одно —
директива `! как аст` заменена на `! как форма-тсд` (иначе редактор показал бы
AST, а не форму).

Открыть: «Примеры» → «Форма ТСД». Файл встроенный (`isBuiltin`): его нельзя
переименовать или затереть — он эталон для сверки рендера с редизайном. Свои
правки — через «Создать файл».

`Кол‑во` в образце написано с **неразрывным дефисом U+2011**, а не с `-`: так
поле таблицы сопоставляется с ресурсом. Замена символа на обычный дефис ломает
сопоставление, поэтому текст примера сверяется с первоисточником в тестах
(включая отдельную проверку U+2011).

## Файлы

| файл | роль |
| --- | --- |
| `../../ast-converters/FlexFormsConvertor.js` | AST → IR формы (порт `target-ast-converter.js`, алгоритм не менялся) |
| `FlexFormsPage.js` | сборка страницы, разметка предпросмотра, имя файла экспорта |
| `FlexFormsStyles.js` | CSS редизайна (сгенерирован, дословно) |
| `FlexFormsRuntime.js` | движок формы (сгенерирован, дословно) |
| `FlexFormsMarkup.js` | каркас страницы + SVG корпуса ТСД (сгенерирован) |
| `../FlexFormsRenderer.js` | рендерер флейвора: рамка, iframe, дебаунс, экспорт |

## Сгенерированные ассеты

Файлы `FlexFormsStyles.js`, `FlexFormsRuntime.js`, `FlexFormsMarkup.js` руками не
правятся — они собираются из первоисточников и проверяются тестом:

```bash
python yarbp/tools/build-flexforms-assets.py           # перегенерировать
python yarbp/tools/build-flexforms-assets.py --check   # сверить (это делает и тест)
```

Источники: `редизайн/kb8-inventory-redesign.html` (CSS, оболочка, движок) и
`flex-forms-legacy/constructor.html` (`getSVG()` — рамка корпуса 346×758 по
viewBox 208×457). Прямоугольник экрана в рамке задан в самом генераторе
(`PREVIEW_SCREEN`): 338×447 со сдвигом 4/80. Отдельной области под экран в
рисунке нет — есть только шапка 1С-клиента (кончается на y=64.9) и клавиатура
(начинается на y=535.6), поэтому прямоугольник подобран по ним: по 4 точки
корпуса с боков, 15 точек до трёх точек меню, 8.6 до клавиатуры (такой же зазор,
как между её кнопками — 5 точек рисунка). Странице формы нужна высота 471
(`PREVIEW_FORM_HEIGHT`: ниже 471 обрезается нижняя панель), а ширина iframe
выведена из пропорции экрана — 356 = 471 × 338 / 447, — поэтому iframe
показывается уменьшенным (`FLEX_FORMS_FORM_SCALE` = 0.94904 = минимум из
отношений по ширине и по высоте) и закрывает экран без тёмных полей. Углы экрана
не скругляются. Легаси-числа `renderMockup()` (308×400 со сдвигом 3/80)
подбирались под старую вёрстку формы и с рисунком не совпадали, поэтому их не
используем.

Почему строки, а не отдельные `.css`/`.js`: экспорт — один файл без сети, а
редактор открывается по `file://`. Прочитать соседний файл и подставить его в
`<script>`/`<style>` в этих условиях нельзя, поэтому исходники лежат в
ES-модулях массивами строк (`[...].join('\n')`).

## Осознанные отличия от легаси-конструктора

1. **Таблица.** В `flex-forms-legacy/constructor.html` у `renderTable` были
   строка итога (`getFooter`: `итог`, `итогЗаголовок`, `итогЗначение`, `колонок`)
   и строка-заготовка для редактируемых таблиц (`getAnEmptyRow`). В редизайне
   их нет, а перенос держит паритет с редизайном побайтово — поэтому итогов и
   пустой строки в предпросмотре тоже нет. Нужны — сначала в дизайн
   (`kb8-inventory-redesign.html`), затем перегенерация ассетов.
2. **Предпросмотр и снимок localStorage.** Движок при загрузке восстанавливает
   из `localStorage` не только значения полей, но и сам IR. В редакторе IR каждый
   раз новый, поэтому `buildFormPage(ir, { preview: true })` вставляет перед
   движком короткий скрипт: IR из снимка выбрасывается, значения полей и `uid`
   остаются (они привязаны к `ид` и переживают правку разметки). В **экспорте**
   этого скрипта нет — файл для ТСД ведёт себя как исходная страница редизайна.
3. **Рамка.** `getSVG()` перенесён символ-в-символ. Отдельной области под экран
   в рисунке нет, поэтому место экрана подобрано по нарисованным шапке
   1С-клиента (кончается на y=64.9) и клавиатуре (начинается на y=535.6):
   338×447 со сдвигом 4/80 в координатах рамки 346×758 — по 4 точки корпуса с
   боков, 15 точек до трёх точек меню, 8.6 до клавиатуры (такой же зазор, как
   между кнопками), углы не скруглены (легаси-раскладка `#ui-mock-container`
   308×400 со сдвигом 3/80 с рисунком не совпадала и обрезала форму справа и
   снизу). Странице формы нужна высота 471 — при меньшей обрезается её нижняя
   панель с кнопкой, — поэтому iframe верстается в этом логическом размере и
   показывается уменьшенным в 0.94904 (`FLEX_FORMS_FORM_SCALE` = минимум из
   отношений по ширине и по высоте), а не пересобирается под экран. Ширина
   iframe (356) выведена из пропорции экрана, чтобы уменьшенная форма закрывала
   его без полей: 471 × 338 / 447 = 356. Рамка подгоняется под панель
   **трансформацией** (`transform: scale()` на `.ff-phone`, размер раскладки
   задаёт обёртка `.ff-phone-scale`), а не пересчётом размеров: экран остаётся
   356×471 в CSS-пикселях, поэтому форма верстается один раз и одинаково
   выглядит и в узкой, и в широкой панели — просто крупнее или мельче.
4. **Кнопка экспорта.** Иконка `static/download-*.svg` объявлена как 800×800,
   поэтому в предпросмотре её размер задан явно (`.ff-export-btn img`, 15px по
   высоте, как `#day-icon` в редакторе). Иначе картинка растягивала кнопку на
   всю панель результата.
5. **Панель редактора.** Предпросмотр живёт в `.ui-render-container` панели
   результата (тот же контракт, что у остальных рендереров): редактор результата
   скрывается, при смене флейвора контейнер удаляется.

## Тесты

```bash
python yarbp/tests/flexforms/run_tests.py               # всё, включая браузер
python yarbp/tests/flexforms/run_tests.py --no-browser  # только логика (quickjs)
```

Проверяется: дословность ассетов, `ast.json → target.json` (побайтово), паритет
собранной страницы с `kb8-inventory-redesign.html` (побайтово), отличие экспорта
от предпросмотра ровно на блок сброса снимка, геометрия рамки, подсказки,
дословность примера «Форма ТСД» относительно первоисточника и дымовой прогон в
Chrome (регистрация флейвора, монтирование предпросмотра **этим примером**, работу
движка внутри iframe, пропуск перерисовки при неизменном IR, а также совпадение
IR примера с `target-sample.json`).
