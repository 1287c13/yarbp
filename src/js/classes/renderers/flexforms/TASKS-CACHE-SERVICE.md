# Задачи к кэш-сервису и расширению 1С

Требования, которые остались **за пределами этого репозитория**: движок формы и
выгрузка конфига здесь готовы, а опубликованная на ТСД страница — нет, потому что
оболочка `фф_ОболочкаФормы` собирается в расширении 1С. Та же редакция лежит в
1С-проекте: `kpp/docs/12-tasks-kesh-rasshirenie.md` (там же контракт конфига —
`kpp/docs/11-tsd-config.md`).

Состояние на момент написания: конструктор выгружает конфиг под контракт
расширения, движок умеет работать с кэш-сервисом — ключ из `?key=` →
`localStorage.ff_token`, заголовок `X-Api-Key` у хука, отправки и пинга,
`Idempotency-Key` у отправки, `401` → `/v1/clients/auth?type=…`. Проверено
живьём: `tests/flexforms/auth-contract.html` (18 проверок, заглушка
`tests/flexforms/auth_server.py`) — зелёное.

Порядок = приоритет; задача 1 обязательна, без неё остальное не видно на ТСД.

---

## 1. Пересобрать оболочку `фф_ОболочкаФормы` из движка (обязательно, расширение)

**Что происходит сейчас.** Публикуемая страница = `CommonTemplate.фф_ОболочкаФормы`
+ конфиг в `<data id="form-params">` (`фф_КонфигТСД.СобратьСтраницу`). Оболочка —
снимок движка, сделанный раньше: в ней нет `?key=`, нет заголовка `X-Api-Key`,
нет `Idempotency-Key` и нет перехода на страницу входа по `401`. Пока оболочка
старая, ключ доступа на ТСД **не работает**: форма получает `401` и молча
показывает «отправка не удалась».

**Что сделать.**

1. Взять текущие встроенные ассеты `src/js/classes/renderers/flexforms/`:
   `FlexFormsMarkup.js` (каркас + SVG корпуса), `FlexFormsStyles.js` (CSS),
   `FlexFormsRuntime.js` (движок).
2. Собрать из них страницу-оболочку: она отличается от обычной только тем, что
   в `<data id="form-params">` лежит маркер (пустой объект), а в шапке — тот же
   `<meta charset>` и CSP с nonce, что в `buildFormPage` (`FlexFormsPage.js`).
3. Заменить тело макета `CommonTemplate.фф_ОболочкаФормы` (`Ext/Template.bin`) и
   прогнать сборку расширения.

**Приёмка.**

- `фф_КонфигТСД.СобратьСтраницу(конфиг)` → в HTML есть подстроки `X-Api-Key`,
  `Idempotency-Key`, `ff_token`, `/v1/clients/auth`; размер вырос примерно на
  2 КБ (проверять не «89 846 символов», а наличие этих подстрок);
- `фф_Тесты.ПрогнатьПриемку` — «Успешно 20 из 20», как сейчас;
- на стенде: форма рисуется, хук и отправка уходят, при стирании ключа из
  `localStorage` и перезагрузке форма сама уводит на страницу входа.

**Чего не делать.** Не менять `РазобратьКонфиг`/`Применить`: формат конфига уже
соответствует, `auth` в конфиге не нужен.

---

## 2. Не вставлять `_AUTH_SHIM` в страницу, которая сама умеет ключ (кэш-сервис)

**Что происходит сейчас.** `core/services.py` (`personalize`) вставляет в выдачу
скрипт `_AUTH_SHIM`. Он не выполняется: CSP страницы — `script-src 'nonce-…'`,
а у вставленного `<script>` nonce нет. То есть на проде работает не шим, а CSP.

**Что сделать.** Одна проверка в `personalize`: если в HTML уже есть `X-Api-Key`
(движок с ключом), шим не вставлять.

```python
if 'X-Api-Key' not in html:
    html = html.replace('</head>', _AUTH_SHIM + '</head>', 1)
```

**Приёмка.** `GET /v1/clients/latest?key=<ключ>` → в ответе нет `_AUTH_SHIM`;
старая страница (без `X-Api-Key`) — шим на месте, поведение прежнее.

**Чего не делать.** Не удалять шим совсем: он прикрывает формы, собранные до
этой доработки.

---

## 3. Без ключа и с `Accept: text/html` — редирект на страницу входа (кэш-сервис)

**Что происходит сейчас.** `GET /v1/clients/latest` без ключа отдаёт
`401 {"ok": false, …}`. Оператор, открывший адрес с планшета (закладка, QR на
стеллаже), видит JSON и тупик: страницы входа нет, вернуться некуда.

**Что сделать.** В `views_api` (или в общем обработчике 401) для этого адреса:

- `Accept` содержит `text/html` и ключа нет → `302 Location: /v1/clients/auth?type=<type>`
  (`type` — из query, иначе тип по умолчанию);
- иначе — как сейчас, `401` JSON (совместимость с клиентами и тестами).

**Приёмка.**

```bash
curl -sI -H 'Accept: text/html' 'http://<host>/v1/clients/latest?type=ПодборТовара'
# 302, Location: /v1/clients/auth?type=%D0%9F%D0%BE%D0%B4%D0%B1%D0%BE%D1%80...
curl -s -o /dev/null -w '%{http_code}\n' 'http://<host>/v1/clients/latest?type=ПодборТовара'
# 401
```

**Чего не делать.** Не менять контракт `401` для `application/json`: на нём
завязаны и мобильный клиент, и приёмка.

---

## 4. Две проверки контракта в `фф_Тесты` (опционально, расширение)

Если есть стенд с прокси — добавить в `фф_Тесты`:

1. «страница без ключа»: `СобратьСтраницу(конфиг)` не содержит ключа доступа,
   но содержит `X-Api-Key`;
2. «401 уводит на вход»: открыть страницу с заведомо негодным `?key=bad`,
   дождаться перехода на `/v1/clients/auth?type=<типКлиента>`.

Без стенда — пропускать (как остальные сетевые проверки приёмки), чтобы прогон
оставался зелёным офлайн.

## Что принято как есть (менять не нужно)

| Решение | Почему |
| --- | --- |
| `Idempotency-Key` ≤ 64 символов, форма шлёт 25 (`a2-1c3f42ab`) | контракт `kpp/docs/02-contract-tsd.md` §6 это допускает; ключ — хэш тела, повтор того же тела даёт `duplicate: true` |
| `POST /processing` принимает `{fields, table}` и только их | движок шлёт ровно это; лишние ключи в теле не появляются |
| в конфиге нет `хэш`, `автор`, `дата`, `auth` | читателей в 1С нет; ключ доступа — только в `localStorage` и заголовке (ADR-13) |
| `watch` — массив имён `Справочник.Имя` / `Документ.Имя` | так его пишет конвертер (`..watch`), так его ждёт подписка обновления кэша |
| `обработчики` — свойство корня без `type` | так его собирает `OBJECT_PROPS` конвертера; разбор в 1С читает корень, а не `children` |
