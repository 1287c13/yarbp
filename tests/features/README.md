# Новые возможности языка и подсветки

Проверки выполняются настоящими модулями редактора в headless Chrome/Edge.
Node не нужен: страница поднимается локальным `http.server`, браузер отдаёт
готовый DOM (`--dump-dom`), раннер разбирает `<pre id="result">`.

## Запуск

Из корня репозитория:

```powershell
python tests/features/run_tests.py
```

## Что покрыто

| Блок | Проверки |
| --- | --- |
| Подстановка вне макроса | пример 2.3, несколько использований, удаление ключа-источника, отсутствие ключа (значение остаётся + диагностика), объект-источник, ортогональность макросам |
| Идентификатор `#id` | `ключ#id:тип` — один узел с полями `key`, `id`, `type`; id у объекта, примитива, массива и элемента массива; ключ без решётки; пустые половины (`поле#`, `#итог`) — не идентификатор; UI-форма берёт имя элемента из поля `id` |
| Директива идентификаторов | `! отключить идентификаторы` и `! disable ids` оставляют `#id` в ключе, действуют на весь документ; `#id` красится цветом ссылок (`.ide-code-id`), не наследует класс ключа и потому не жирный, при выключенных идентификаторах — не красится; CSS-цвета светлой и тёмной темы |
| Фрагмент кода | одинарный и тройной fence, язык и его отсутствие (`language: null`), сырой текст, снятие отступа fence, `valueType: CODE`, позиция содержимого, отсутствие токенов внутри острова, параметр макроса, незакрытый блок |
| Значение с новой строки | многострочная строка (без хвостового перевода), число, булево, null, фрагмент кода, отсутствие значения (диагностика «ожидалось значение», AST как раньше) |
| Кейс 44 | исходная разметка `44_bsl_code.txt` и ожидаемая разметка дают эквивалентный AST; оба вида fence дают CODE-узлы |
| Конвертеры | JSON/XML/proto не падают на фрагменте кода и сохраняют сырой текст |
| UI: таблица записей | стартует пустой с подсказкой; «Добавить запись» создаёт строку, счётчик и скрывает пустое состояние; колонки `поле:выбор`/`поле:флаг` рисуют select/checkbox; Enter ведёт в ту же колонку следующей строки и создаёт новую на последней; удаление перенумеровывает строки и возвращает пустое состояние; `restore()` восстанавливает строки, select и флаг |
| Подсветка | границы и язык в основном слое, отложенный проход по кулдауну 150 мс, BSL в традиционной схеме 1С (красные ключевые слова/операторы, синие идентификаторы, зелёные комментарии, чёрные строки/числа, коричневый препроцессор), JS/SQL, отсутствие запуска без языка, неизменность текста, экранирование HTML, сохранение курсора и выделения в редакторе |
| Ссылки и макросы | `(( имя ))` красится только при найденном ключе, ключ-источник — без префикса и только когда подставлен, `@макрос` — всегда, места подстановки в теле макроса не красятся даже при найденном ключе верхнего уровня; текст подсветки не меняется; CSS-цвета светлой/тёмной темы, отсутствие класса `ide-code-macro-param`, отсутствие подложки у фрагмента кода и тёмный ползунок скролла |
| Рамки директив | соседние строки-директивы получают одну общую рамку (её высота — две строки), директивы через текст — каждая свою; рамка идёт по краю зелёной подложки, а не по её прямоугольнику (`<path>` в SVG: у строк разной длины — ступенькой, при разрыве внутри — разрыв), линия 0.5px стоит на 2px левее и правее текста, углы скруглены дугами радиуса 5, у выпуклых углов дуга идёт наружу (`sweep-flag 1`), у вогнутого — внутрь (`0`); текст слоя подсветки не меняется, внутри рамок текста нет; слой рамок стоит на начале текста вместе с желобком номеров строк, полотно не обрезает контуры; документ без директив рамок не создаёт |
| Подсказки | внутри CODE_BLOCK меню не вызывается (включая Alt и `force`), на fence тоже; вне блока контекстные подсказки работают; у конвертера без словаря — только директивы в начале пустого файла (курсор в позиции 0) и внутри уже распознанной директивы, в пустых строках ниже начала файла меню нет; у конвертера со словарём контекст работает вне директив |
| L-2: разбор сахара | `! разбор-сахара(тег) …` разворачивает `value` в явные `.свойства`; правило без тега действует на все теги, частное важнее; AST-эквивалентность явной записи, разделители `/` и `//`, пустые сегменты, конфликт с явным свойством, malformed без диагностики, порядок директив и флейвор, одинаковый HTML UI-генератора |
| Директива без тела | `! ` — это `DIRECTIVE` с пустым значением, покрывающий сам `!`: границы токена `0..1`, подсветка `<span class="flavor">!</span>`, позиция директивы в AST в корне документа, отступ остаётся вне токена; у директивы с телом диапазон прежний; `replaceFrom` подсказки начинается с `!`, поэтому вставка не дублирует его |
| L-1: импорт | `! импорт <объект> из <файл>`; имя файла без пробелов или в кавычках, malformed без диагностики, неизвестный файл/объект, дубль ключа, self/ambiguous, `origin`, позиция директивы, сахар файла-источника |

Рамки директив — отдельный слой (`src/js/classes/highlighters/FlavorFrames.js`):
рамку рисует не `outline` на `span.flavor`, а `<path>` в SVG, поэтому соседние
строки получают одну общую рамку, а не две соприкасающиеся. Геометрия — контур
объединения прямоугольников подложки (`getClientRects` каждого
`span.flavor`), поэтому у директивы из строк разной длины линия идёт
ступенькой, а не по описанному прямоугольнику. Прямоугольники расширяются на
2px влево и вправо (`FRAME_PADDING_X`): подложка начинается ровно с текста, и
линия по её краю прилипала к буквам; вертикальных отступов нет — иначе контур
рвался бы на стыке строк. Углы скругляются дугами радиуса 5 (`CORNER_RADIUS`,
как прежний `border-radius: 5px`), радиус прижимается к половине короткого из
соседних рёбер, чтобы у крошечного шага ступеньки дуги не налезли друг на
друга. Направление дуги — по виду угла: контур обходится по часовой стрелке,
поэтому выпуклый угол скругляется дугой по часовой (`sweep-flag 1`) и срезает
вершину наружу, а вогнутый — против (`0`) и уходит внутрь, к материалу. С одним
и тем же флагом дуга вогнутого угла выпирала в пустоту: на ступеньке директивы
из строк разной длины получался бугор. Обводка тоньше прежней рамки:
`stroke-width: 0.5` — контур в `<path>` центрируется на линии, 1px выглядел
толще `border`'а, а 0.75px на экране с двойной плотностью даёт полтора
физических пикселя, то есть снова жирную линию; 0.5 — ровно один. Чистый
алгоритм контура (`unionOutlines`) и разметка `d` (`framePath`) проверяются на
искусственных прямоугольниках: ступенька из шести вершин, два контура при
разрыве, все выпуклые углы прямоугольника против единственного вогнутого у
ступеньки.

## Отношение к существующим тестам

`tests/lexer` остаётся golden-набором лексера/парсера. Новые кейсы лежат в
`notes/cases/32_...`–`44b_...` и добавлены в `tests/lexer/cases.json`. Снимок
`12_macro` осознанно переснят под новый порядок вызова макроса
(`имя-результата(имя-макроса)`); остальные существующие снимки не менялись.

Диагностики (`lexer.diagnostics`, `parser.lastDiagnostics`) намеренно не входят
в golden-снимки: это нефатальные замечания, которые видит строка статуса, а
токены и AST остаются прежними.
