# Новые возможности языка и подсветки

Проверки выполняются настоящими модулями редактора в headless Chrome/Edge.
Node не нужен: страница поднимается локальным `http.server`, браузер отдаёт
готовый DOM (`--dump-dom`), раннер разбирает `<pre id="result">`.

## Запуск

Из корня репозитория:

```powershell
python tests/features/run_tests.py
```

## Что покрыто

| Блок | Проверки |
| --- | --- |
| Подстановка вне макроса | пример 2.3, несколько использований, удаление ключа-источника, отсутствие ключа (значение остаётся + диагностика), объект-источник, ортогональность макросам |
| Фрагмент кода | одинарный и тройной fence, язык и его отсутствие (`language: null`), сырой текст, снятие отступа fence, `valueType: CODE`, позиция содержимого, отсутствие токенов внутри острова, параметр макроса, незакрытый блок |
| Значение с новой строки | многострочная строка (без хвостового перевода), число, булево, null, фрагмент кода, отсутствие значения (диагностика «ожидалось значение», AST как раньше) |
| Кейс 44 | исходная разметка `44_bsl_code.txt` и ожидаемая разметка дают эквивалентный AST; оба вида fence дают CODE-узлы |
| Конвертеры | JSON/XML/proto не падают на фрагменте кода и сохраняют сырой текст |
| Подсветка | границы и язык в основном слое, отложенный проход по кулдауну 150 мс, BSL в традиционной схеме 1С (красные ключевые слова/операторы, синие идентификаторы, зелёные комментарии, чёрные строки/числа, коричневый препроцессор), JS/SQL, отсутствие запуска без языка, неизменность текста, экранирование HTML, сохранение курсора и выделения в редакторе |
| Подсказки | внутри CODE_BLOCK меню не вызывается (включая Alt и `force`), на fence тоже; вне блока контекстные подсказки работают |
| L-2: типизация сахара | `! типизация-сахара(тег) …` разворачивает `value` в явные `.свойства`; AST-эквивалентность явной записи, разделители `/` и `//`, пустые сегменты, конфликт с явным свойством, malformed без диагностики, порядок директив и флейвор, одинаковый HTML UI-генератора |

## Отношение к существующим тестам

`tests/lexer` остаётся golden-набором лексера/парсера. Новые кейсы лежат в
`notes/cases/32_...`–`44b_...` и добавлены в `tests/lexer/cases.json`. Снимок
`12_macro` осознанно переснят под новый порядок вызова макроса
(`имя-результата(имя-макроса)`); остальные существующие снимки не менялись.

Диагностики (`lexer.diagnostics`, `parser.lastDiagnostics`) намеренно не входят
в golden-снимки: это нефатальные замечания, которые видит строка статуса, а
токены и AST остаются прежними.
