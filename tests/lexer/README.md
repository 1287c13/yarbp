# Золотые тесты лексера и парсера

Тесты фиксируют **текущее** поведение системы на кейсах из `notes/cases`.
Они нужны как страховка перед переделкой лексера: если изменится поток
токенов, AST или рендер, тест покажет первое расхождение.

Для каждого кейса снимается:

- поток токенов лексера: `type`, `value`, `prefix`, `start`, `end`, `error`;
- AST после парсера (включая раскрытие макросов);
- рендер флейвора из первой директивы: `lexer`, `ast`, `json`, `xml`, `proto`;
- ошибки токенизации, парсинга и конвертации — они тоже входят в снимок.

Это снимки фактического поведения, а не рендеры из `notes/cases`: текущее
поведение приемлемое, хотя и не идеальное. Если расхождение осознанное,
снимки переснимаются вручную.

## Запуск

Из корня репозитория:

```bash
python yarbp/tests/lexer/run_tests.py           # проверка
python yarbp/tests/lexer/run_tests.py --update  # пересъёмка снимков
python yarbp/tests/lexer/run_tests.py --help
```

Нужен Chrome или Edge. Node и quickjs не нужны: ES-модули редактора
выполняются в headless-браузере, как в `tests/flexforms`. Раннер сам
поднимает локальный `http.server` на корень репозитория и передаёт
страницу в `--dump-dom`.

`--update` печатает, какие снимки изменились, и пишет их в
`tests/lexer/golden/`. Перед обновлением полезно посмотреть diff: если
изменился вход кейса из `notes/cases`, это тоже повод осознанно
переснять поведение.

## Состав

| файл | что это |
| --- | --- |
| `cases.json` | список кейсов из `notes/cases`, участвующих в тестах |
| `cases.html` | браузерная страница: читает кейсы, строит снимки, сравнивает с golden |
| `run_tests.py` | раннер: сервер, headless-браузер, разбор результата, `--update` |
| `golden/<кейс>.json` | снимок текущего поведения |

Кейс — это текст до строки `render`, `render:` или до первой таблицы
`+---+`: таблицы в кейсах 4/7/9/10/13/14/15 и `obj_after_nested_arr` —
человекочитаемый рендер, тестами он не используется.

Файла `8_obj_props_after_nested_obj.txt` в `notes/cases` нет; `XPM_arrows.md`
не относится к лексеру и в манифест не включён.

При добавлении кейса:

1. положите `.txt` в `notes/cases`;
2. добавьте имя файла в `cases.json`;
3. выполните `python yarbp/tests/lexer/run_tests.py --update`;
4. проверьте diff нового `golden/<кейс>.json` и запустите тесты без `--update`.

`obj_after_nested_arr.txt` не содержит директивы: как и в редакторе,
эффективный флейвор для него — `lexer`.
