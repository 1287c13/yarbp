# Тесты флейвора «форма-ТСД»

```bash
python yarbp/tests/flexforms/run_tests.py               # всё (нужен Chrome/Edge)
python yarbp/tests/flexforms/run_tests.py --no-browser  # только логика (нужен quickjs)
python yarbp/tests/flexforms/run_tests.py --help
```

| файл | что это |
| --- | --- |
| `run_tests.py` | раннер: дословность ассетов, золотой тест конвертера, паритет страницы с редизайном, экспорт/предпросмотр, геометрия, подсказки, пример «Форма ТСД» в редакторе, браузерный дым |
| `smoke.html` | страница дымового теста: настоящие модули редактора + настоящий пример из «Примеров» |

`smoke.html` поднимается локальным `http.server` на корень репозитория (ES-модули
не грузятся с `file://`), браузер запускается в headless-режиме с `--dump-dom`,
вердикт читается из `<title>` и `<pre id="result">`, а IR, собранный из примера, —
из `<pre id="ir">` (он сверяется с `target-sample.json` побайтово).

Разметку дым не копирует: он берёт текст предопределённого примера «Форма ТСД»
прямо из `FileManager` (`builtin-9`), то есть проверяет то, что видит
пользователь. Поэтому шаг «пример → IR образца» идёт только в браузере: в
`quickjs` (`--no-browser`) лексер не заводится (нет TDZ для статических полей
класса), и без браузера печатается `skip` с этой причиной.

`run_tests.py` умеет запускать JS-модули без Node: он снимает `import`/`export`
и склеивает модуль с его локальными зависимостями для `quickjs`. Если такой
модуль добавит нестандартный синтаксис модулей, тест упадёт с явной ошибкой
«модульный синтаксис не снят», а не промолчит.

Шаг «геометрия» держит контракт предпросмотра: место экрана в рамке — 338×447
со сдвигом 4/80 в координатах 346×758 (по 4 точки корпуса с боков, 15 точек до
трёх точек меню и 8.6 до клавиатуры — такой же зазор, как между её кнопками;
отдельной области под экран в SVG нет, числа подобраны по рисунку), углы не
скруглены, а сам iframe верстается в логических 356×471 и вписывается в экран
уменьшением (`transform: scale(0.94904)`, минимум из отношений по ширине и по
высоте) — при меньшей высоте форма обрезала бы нижнюю панель. Ширина iframe
выведена из пропорции экрана (471 × 338 / 447), поэтому уменьшенная страница
закрывает экран целиком (отдельная проверка — расхождение меньше пикселя): иначе
по краям экрана появились бы тёмные поля.
В браузере дополнительно проверяется, что этот логический размер не
зависит от панели (рамка подгоняется `transform: scale()`, а не пересчётом
размеров), что iframe действительно уменьшен до экрана, что у экрана нет
скругления углов, и что иконка кнопки
экспорта ограничена по высоте: `download-*.svg` объявлена как 800×800 и без
ограничения растягивала кнопку на всю панель.

Поведение формы проверяется в том же прогоне, на живой странице внутри iframe —
это ровно те места, где ручной перенос расходился с редизайном:

| проверка | что ловит |
| --- | --- |
| `readOnly` + `inputmode="none"` у поля количества и набор символов в него по `keydown` | «с выключенной клавиатурой нельзя ввести»: поле обязано оставаться `readonly`, а ввод — идти через мост сканера (`initScannerBridge`), как keyboard-wedge на ТСД |
| `getComputedStyle(...).appearance === 'none'` | типовой спиннер `input[type=number]`, который всплывает по наведению, если `all:unset` из редизайна не доехал в редактор |
| `#track` → `translateX(-100%)` + `#stepNow` = `2` после синтетического свайпа | и листание жестом, и анимацию перехода: их делает движок страницы, а не рендерер |
| `data-theme` + `tsd-theme` в `localStorage`, и та же тема в новом iframe после перерисовки | сброс выбранной темы при повторном рендере |

Описание флейвора и осознанных отличий от легаси — в
`yarbp/src/js/classes/renderers/flexforms/README.md`.
