# Конвертеры и AST

Smoke-тесты всей цепочки «разметка → AST → артефакт». Проверки выполняются
настоящими модулями редактора в headless Chrome/Edge, Node не нужен.

## Запуск

```powershell
python tests/converters/run_tests.py
```

## Что покрыто

| Конвертер | Проверки |
| --- | --- |
| JSON | результат — объект, числа остаются числами, `yes` → `true`, вложенный объект и массив, пустой AST отклоняется |
| XML | непустой результат, именованный корень из разметки, документ разбирается XML-парсером |
| Protobuf | непустая схема, поля объекта описаны |
| UI | генератор не падает, HTML непустой и без `undefined` |
| BPMN | непустой XML с `definitions`, документ разбирается XML-парсером |
| Форма-ТСД | IR из встроенного примера: корень `форма`, операции и поля на месте |

## Golden-снимки BPMN XML

`cases/*.yarbp` — документы, `golden/<имя>.json` — снимок вывода: полный XML
плюс счётчики (`processes`, `tasks`, `gateways`, `events`, `flows`, `lanes`,
`shapes`, `edges`, `waypoints`). Так ловится регресс в раскладке, порядке DI и
сериализации, который smoke-проверки не видят.

Пересъёмка после **осознанного** изменения вывода:

```powershell
python tests/converters/run_tests.py --update
```

Документы в наборе:

| Файл | Что фиксирует |
| --- | --- |
| `bpmn_lanes_gateway` | процесс, дорожки, событие, задача, шлюз с двумя ветками — пример из readme без пустых строк |
| `bpmn_branches_artifacts` | ветки, `.тип сервис`, `повторение цикл`, комментарий, данные, база данных |
| `bpmn_subprocess` | подпроцесс с внутренней цепочкой, `тип пользователь`, `повторение последовательно` |

`cases/bpmn_readme_example.yarbp` — пример из readme **как есть**. Он в снимки
не входит: сейчас даёт пустую модель, см. «Известные проблемы».

## Известные проблемы (наблюдения, не требования)

1. **proto и массивы:** для `..items` схема выходит `message Item {}` без полей —
   значения элемента в неё не попадают; набор печатает `skip proto`.
2. **XML и анонимный корень:** если документ начинается с `:`, на выходе
   несколько элементов верхнего уровня — это не XML-документ; с именованным
   корнем всё корректно.

Исправлено (было в этом же разделе раньше):

- **пустые строки** — на LF лексер к ним и раньше был не чувствителен; «поломка»
  оказалась **CRLF** в фикстурах. Теперь `FileManager` нормализует переводы
  строк при импорте и загрузке файла (плюс защитный гвард в лексере);
- **шлюз внутри задачи** — `buildTask` достраивает цепочку из вложенных
  потоковых узлов, поэтому пример из readme работает как написан и лежит в
  golden-снимках.
