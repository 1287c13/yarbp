# Регрессии безопасности

Набор отвечает на один вопрос: **на входе тег — на выходе нет живого тега**.
Проверки выполняются настоящими модулями редактора в headless Chrome/Edge
(как `tests/lexer` и `tests/flexforms`), поэтому видят ровно тот HTML, который
собирает продукт. Node и npm не нужны.

## Запуск

```powershell
python tests/security/run_tests.py
```

Раннер сам поднимает `http.server`, открывает `security.html` браузером
(`--headless=new --dump-dom`) и разбирает `<pre id="result">`. Код возврата 0 —
все проверки зелёные.

## Что покрыто

| ID | Проверка |
| --- | --- |
| — | `escText`/`escAttr`/`escJsonForHtml`: набор символов и валидность JSON |
| D-01 | `buildFormPage` с тегом в IR: в странице нет `<img`, в `<data>` нет дочерних узлов, `JSON.parse(textContent)` возвращает исходный IR; движок не обращается к `#form-params` через `innerHTML` |
| D-02 | в шаблонах движка нет сырых `id="${id}"`, `${fieldParams['имя']}`, `${option['имя']}`; и функционально — в iframe с испорченным IR поле отрисовано, `id` сохранён значением, имя показано текстом, `window.__xss` не выставлен |
| D-03 | список файлов с `id` из импортируемого JSON: нет `<img>`, нет лишних атрибутов, `dataset.id` равен исходному |
| D-04 | `YarbpHighlighter.highlight()`: нет `<img`, в DOM нет узла `IMG`, текст подсветки совпадает с исходным |
| D-14 | панель результата для `as lexer` / `as ast` / `as json` / `as proto`: нет `<img>`, текст подсветки равен тексту результата |

## Как добавить проверку

Проверки — это `check(имя, условие, подробность)` в `security.html`. Строки
`ok`/`FAIL` уходят в `<pre id="result">`, итог — в `<title>` страницы.
Для новых мест сборки HTML порядок такой:

1. найти в коде вставку пользовательских данных в `innerHTML`;
2. подставить в неё `PAYLOAD` (`<img src=x onerror=...>`) и отрисовать;
3. проверить через DOM, а не строкой: `querySelector('img')`, `textContent`,
   `dataset` — строковый `indexOf('<img')` не видит, например, `<IMG>`.
