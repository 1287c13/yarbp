# Автодополнение: UX и валидность вставки

Статус: **реализовано** (2026-11-19), **итерация 2 — реализована** (2026-11-20),
**баг `! ` (директива без тела) — исправлен** (2026-11-20).
Дизайн и анализ — 2026-11-15; сценарный UI-тест — `tests/autocomplete`.

## 1. Цель

Автодополнение должно помогать набирать ЯРБП, но не мешать:

- в начале строки `Tab` делает отступ, а не принимает случайную подсказку;
- подсказка при этом доступна явно, и пользователь видит, как её вызвать;
- после выбора подсказки в документе остаётся синтаксически корректная
  конструкция, а курсор оказывается там, где ожидает пользователь;
- меню не открывается в неподходящий момент и не перекрывает ввод;
- одинаково предсказуемо работают мышь, `Tab`, `Enter`, стрелки и `Escape`.

Ориентир UX — PyCharm/IDE: completion не должен «воевать» с Tab,
автодополнением по точке и обычным переносом строки.

## 2. Что было до реализации

Поток:

```text
input → scheduleSuggestions (Ticker 120 мс)
      → SuggestionProvider.update
      → resolveDirectiveContext / resolveFlavorContext
      → SuggestionUI.show
```

- `Alt` в `app.js` вызывает `update(..., force: true)`.
- `SuggestionUI.handleKey`:
  - в режиме списка: `ArrowUp/Down`, `Tab` — принять, `Escape` — закрыть;
  - в режиме подсказки: только `Escape`; `Tab` не перехватывается и уходит
    в `app.js`, где вставляет два пробела.
- В начале строки `resolveFlavorContext` возвращает не список, а
  `hint: '▼ Alt'`; это уже даёт нужный базовый сценарий «Tab = отступ».
- Вставка делается через `SuggestionUI.apply()`:
  `setRangeText(s.insert, replaceFrom, selectionStart, 'end')`.
- Для значений с `replace: false` текст вставляется в курсор без замены
  слова.

## 3. Найденные риски

### 3.1. Подсказка в начале строки есть, но объясняет мало

Сейчас hint — `▼ Alt`. Пользователь не понимает:

- что `Tab` в этом состоянии делает отступ;
- что подсказки можно вызвать не только мышью;
- что после `Alt` список откроется, а `Tab` его примет.

Нужен короткий, но явный hint: например
`Alt — подсказки · Tab — отступ` (текст требует утверждения).

### 3.2. `Tab` зависит от того, успел ли открыться список

Автосписок открывается с задержкой Ticker. В начале строки это hint, но
после ввода пробелов/символов состояние может измениться. Пользователь
нажимает `Tab` и получает то отступ, то принятие подсказки — в зависимости
от гонки таймера и фокуса. Нужен явный state machine и блокировка
автопоказа в начале строки до первого непробельного символа.

### 3.3. Вставка не является «контрактом»

Сейчас `insert` — готовая строка с пробелами и переводами строк, например:

```js
{ insert: '..аннотации\n      ' }
```

Проблемы:

- отступ внутри шаблона абсолютный, а не относительно текущей строки;
- если курсор уже после пробела, можно получить двойной пробел;
- если в тексте уже есть `= ` или атрибут, вставка может его дублировать;
- многословные значения вроде `суммировать в приемнике` заменяют только
  последнее слово (`currentWord`), а не всё значение;
- нет явного места для курсора после вставки: шаблон с несколькими строками
  оставляет курсор в конце, а не в первой редактируемой позиции.

### 3.4. Замена диапазона не учитывает выделение

`SuggestionUI.apply()` берёт `end = ta.selectionStart`, а не
`selectionEnd`. Если в редакторе выделен фрагмент, `Tab` заменит только
левую границу выделения. Нужно либо запрещать автопринятие при
непустом выделении, либо заменять весь выделенный диапазон.

### 3.5. Контекст не покрыт матрицей

Тесты `tests/features` проверяют только подавление подсказок внутри
`CODE_BLOCK`. Нет проверок:

- начала строки и `Tab`;
- `Alt` → список → `Tab`;
- `= `, `.атрибут`, вложенного отступа;
- значений с `replace: false` (XPM `..связи`);
- выбора мышью;
- выделения;
- повторного открытия после принятия.

### 3.6. Позиционирование и доступность

- `position()` считает колонку как число символов, но не учитывает
  `tab-size`, широкие Unicode-символы и переносы строк;
- popup не переворачивается вверх у нижней границы;
- у списка нет `role="listbox"`, `aria-activedescendant`, связи
  textarea ↔ popup;
- hint не объявляется screen reader-ом.

## 4. Предлагаемый UX

### 4.1. Состояния

```text
Idle
  │ ввод символа / Alt / Ctrl+Space
  ▼
List ── Tab/Enter ──► Idle (принято)
  │ Escape
  ▼
Hint (только начало строки)
  │ Alt / Ctrl+Space
  ▼
List
```

### 4.2. Клавиши

| Клавиша | Нет списка | Список открыт |
| --- | --- | --- |
| `Tab` | отступ/выравнивание | принять подсказку |
| `Shift+Tab` | убрать отступ | убрать отступ, список закрыть |
| `Alt` | открыть список | переоткрыть/обновить список |
| `Ctrl+Space` | открыть список (рекомендуемый второй shortcut) | обновить список |
| `↑` / `↓` | обычное движение курсора | выбор варианта |
| `Enter` | новая строка | принять вариант (нужно подтвердить) |
| `Escape` | — | закрыть список/hint |
| клик по варианту | — | принять вариант |

`Enter` как принятие — спорный пункт: в DSL Enter часто нужен для новой
строки. Предлагаю включить его только когда список реально открыт и
пользователь не редактирует многострочное значение; решение за владельцем.

### 4.3. Начало строки

- Автоматически показывать **только hint**, не список.
- `Tab` всегда делает отступ; hint остаётся видимым.
- Явный `Alt` (и, если подтвердим, `Ctrl+Space`) открывает список.
- В hint явно написано, как вызвать подсказки и что Tab делает отступ.
- После первого непробельного символа hint заменяется обычным списком,
  если есть подходящий контекст.

### 4.4. Контракт подсказки

Каждый вариант должен описывать не только `label/insert`, но и:

- `replaceRange` — точный диапазон замены (токен/значение/слово);
- `indent` — `none` / `current` / `relative`;
- `cursor` — позиция курсора после вставки (маркер или смещение);
- `allowIncomplete` — шаблон намеренно оставляет незаполненное место;
- `suppressNextAutoShow` — не открывать меню сразу после принятия.

Вставка должна:

1. заменять весь смысловой диапазон, а не последнее слово после пробела;
2. пересчитывать отступы относительно текущей строки;
3. не дублировать `=`, пробелы и уже введённые атрибуты;
4. ставить курсор в явно заданную позицию;
5. не открывать новое меню в тот же тик, если это не следующий
   осмысленный контекст.

### 4.5. Валидность

Для каждого варианта подсказки нужен сценарный тест «применить и
разобрать»:

```text
seed-документ + контекст
  → применить suggestion.insert
  → lexer + parser
  → нет новых ошибок (или ожидаемая incomplete-диагностика)
  → AST содержит ожидаемый ключ/атрибут/значение
```

Шаблоны, которые намеренно создают каркас (например, `..роли`), должны
явно помечаться `allowIncomplete` и проверяться отдельным ожидаемым
диагностическим профилем.

## 5. Матрица сценариев

| # | Контекст | Действие | Ожидание |
| --- | --- | --- | --- |
| 1 | пустая строка, курсор в начале | `Tab` | два пробела, документ не меняет смысл |
| 2 | пустая строка + hint | `Alt` | список корневых ключей, hint заменён списком |
| 3 | список корня | `Tab` | вставлен валидный корневой ключ, курсор после `= ` |
| 4 | `задача = сер` | ввод/`Tab` | `задача = сервис`, без дублей |
| 5 | `задача .тип ` | список значений | выбран тип, ровно один пробел |
| 6 | вложенная строка с отступом | выбор шаблона | отступы пересчитаны относительно строки |
| 7 | XPM `..связи ` | `replace:false` | стрелка добавлена, старое значение не съедено |
| 8 | выделен фрагмент | `Tab` | либо отступ, либо замена всего выделения — без «полузамены» |
| 9 | код-блок | ввод/`Alt` | подсказок нет |
| 10 | после принятия | автообновление | меню не мигает и не открывается без нужды |
| 11 | низ экрана | открытие | popup переворачивается вверх |
| 12 | Tab в тексте с табами | открытие | popup совпадает с курсором |

## 7. Принятые решения

1. `Enter` **не** принимает вариант: только перенос строки.
2. `Ctrl+Space` добавлен вторым shortcut-ом к `Alt`.
3. Hint: `▼ Alt` (в итерации 1 было `Alt — подсказки · Tab — отступ`,
   см. 9.1).
4. При непустом выделении `Tab` не принимает подсказку: меню закрывается,
   отступ делает редактор. Клик мышью заменяет выделение целиком.
5. Шаблоны, создающие каркас (`..опции`, `:`, `:обработчики`), считаются
   валидными после заполнения обязательных мест; тест проверяет конечный
   документ, а не каждый промежуточный шаблон.

## 8. Что реализовано

- `SuggestionUI` — состояния `Idle/Hint/List`, `Escape`, `Tab`/`Shift+Tab`,
  стрелки, клик мышью, ARIA, переворот popup, `$0` и относительные отступы,
  `dedent` для повторных строк `:` в таблицах/опциях/обработчиках.
- `SuggestionProvider` — ранжирование по префиксу (в итерации 2 фильтрация
  заменена ранжированием, см. 9.3), подсказки
  директив в пустом документе, `Ctrl+Space`, контекст анонимных объектов
  (`containers`), ключи с типом (`поле:штрихкод`, `.приемник:…`),
  многословные значения и `replace:false` для стрелок XPM.
- `contextResolver` — `ownerKey`/`ownerIndent`, `anonymous`, `valueStart`;
  ключ с суффиксом-типом остаётся ключом, пока на строке нет `=`.
- `flexFormsSuggestions` — полный словарь актуальной разметки ТСД: шапка,
  `..подписки`, `:обработчики`, операции, поля, опции, таблица и колонки.
- `tests/autocomplete` — сценарный UI-тест, который собирает форму
  только подсказками и проверяет итоговый IR.

## 9. Итерация 2: улучшения UI/UX (2026-11-20)

Замечания пользователя и что именно правим. Ничего из этого тест
`tests/autocomplete` раньше не ловил: он проверял наличие `<li>` в DOM, а не
то, что список действительно виден.

### 9.1. Hint вместо фразы — пиктограмма раскрытия + `Alt`

Было: `Alt — подсказки · Tab — отступ`. Нужно: `▼ Alt` (чёрный
треугольник вниз + подпись клавиши). Фраза слишком длинная и визуально
конкурирует с кодом; `Tab` и так делает отступ, это поведение по умолчанию.

- [x] `SuggestionProvider`: `HINT = '▼ Alt'`.
- [x] CSS: hint читается как чип (моноширинный, приглушённый, без переноса).
- [x] Тест: hint содержит `▼` и `Alt`; проверка «объясняет Tab» убрана.

### 9.2. Меню открывается «тонкой полоской» (баг)

Причина: в `SuggestionUI.show()` ветка списка вызывает
`renderList(); renderDoc(); renderHint(null)`, а `renderHint(null)` прячет
`<ul class="suggestion-list">`. В popup остаются рамка и пустой hint —
полоска. Стрелки вызывают `renderList()` повторно и «включают» список.

- [x] В режиме списка гасить только `hintBox`, не трогая список и доки.
- [x] `renderHint()` оставить для hint-режима (он и должен прятать список).
- [x] Тест: после `Alt`/ввода `list.hidden === false`, у popup ненулевая
  высота, `<li>` видимы.

### 9.3. Не фильтр, а ранжирование

Было: `matchVariants` выбрасывал варианты без совпадения по префиксу, и при
вводе `з` оставались только `.заголовок*`. Нужно: показывать **все**
варианты, но совпавшие поднимать наверх (exact → startsWith → alias →
подстрока → остальные в исходном порядке).

- [x] `SuggestionProvider.matchVariants` возвращает все варианты, сортирует
  по score и сохраняет исходный порядок внутри группы.
- [x] Активный элемент — первый в отсортированном списке (совпадение по
  префиксу), а не случайный.
- [x] Тест: после `з` видны и `.заголовокФормы`, и остальные свойства формы;
  первый — совпавший. Уточнение поднимает нужный вариант на позицию 0,
  но не сокращает список до одного.
- [x] README/док: «сокращает список» → «поднимает совпадения наверх».

### 9.4. Popup не следует за кареткой при перемещении мышью

`input` не срабатывает при клике/перемещении каретки, поэтому меню остаётся
на старой позиции и в старом контексте.

- [x] `app.js`: `document.selectionchange` + `textarea.mouseup` — если меню
  открыто и фокус в редакторе, пересчитать подсказки для новой каретки
  (`scheduleSuggestions`), а не только двигать popup.
- [x] `textarea.scroll` — `suggestionUI.refresh()` (popup не отрывается от
  каретки при прокрутке).
- [x] Тест: открыть список, перенести каретку мышью (`setSelectionRange` +
  `mouseup`), дождаться — `popup.style.left/top` изменились, контекст новый.

### 9.6. Два серых текста под списком сливались

Было: под `<ul>` подряд шли `blockDoc` (контекст: «Свойства формы») и
`doc` активного варианта («Заголовок в шапке ТСД»). Обе строки — мелкий
серый текст на одном фоне, разделённые только линией: непонятно, где
контекст, а где описание, и к чему относится вторая строка.

Рассмотренные варианты:

1. **Описание варианта переносим наверх**, контекст — вниз: меняет местами
   ту же путаницу, плюс контекст внизу читается как подпись к списку.
2. **Описание прямо под активным `<li>`** (как в fish): строка «прыгает»
   при каждом `↑`/`↓` и при наведении мыши, элементы списка меняют высоту,
   ломается `scrollIntoView` и `max-height`. Дорого и дёргано.
3. **Описание справа от списка** (как documentation popup в PyCharm):
   требует второго позиционируемого блока и легко уезжает за край экрана
   на узких панелях.
4. **Принято: контекст — шапка popup, описание — футер popup.** Позиция
   однозначно отвечает на вопрос «что это»: над списком — заголовок того,
   что в списке; под списком — пояснение к выделенной строке (как
   detail-строка в VS Code). Плюс разные роли типографикой: контекст 10px
   приглушённый на подложке, описание 11px обычного цвета.

- [x] `SuggestionUI`: порядок в popup — `blockDoc` → `<ul>` → `itemDoc` → hint.
- [x] CSS: шапка с `border-bottom` и подложкой, футер с `border-top`;
  popup получил `overflow: hidden`, чтобы подложки не вылезали за скругление.
- [x] Тёмная тема: подложки `#333`, разделители `#444`.
- [x] Тест: порядок детей popup, текст шапки = «Свойства формы», футер =
  описание активного варианта и меняется после `ArrowDown`; в hint-режиме
  ни списка, ни доков нет.

## 10. Директива без тела (`! `) — 2026-11-20

Было: пользователь набирает `!` и пробел в пустом файле. Лексер выпускает
`DIRECTIVE` с пустым значением, а `recalcBounds` сдвигал начало токена на
длину префикса только при непустом значении (`if (token.prefix &&
token.value)`). Следствия:

- диапазон токена начинался с пробела после `!`, поэтому подсветка флейвора
  рисовала полоску без восклицательного знака;
- позиция директивы в AST была `start = 1`, и `isRootDirective` считал её
  директивой не нулевого отступа (`sourceText.slice(0, 1) === '!'`) — то есть
  «не в корне документа»;
- подсказки начинали замену с `token.start` (позиция пробела), поэтому `Tab`
  оставлял исходный `!` и вставлял второй: `! ! как `, разметка ломалась.

Стало: пустая директива — ровно её префикс (`0..1` для `! `). `recalcBounds`
для такого токена не вычитает длину префикса, а сразу ставит границы префикса,
поэтому лексер, AST, подсветка и подсказки видят один диапазон.

Отдельно `SuggestionProvider.resolveDocumentContext` — запасная ветка, которая
срабатывает, когда токена директивы на строке ещё нет (например, обновление
подсказок пришло раньше, чем лексер собрал токен): если слово не набрано, а на
строке есть `!`, замена начинается с `!`, а не с каретки. Иначе вставка
«! имя» добавляла второй `!` уже в этой ветке.
