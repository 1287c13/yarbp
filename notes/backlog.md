# Бэклог доведения YARBP

> Рабочий план: только технические баги и инженерная гигиена. Продуктовый
> дизайн, новые конвертеры и крупные фичи сюда не входят.
>
> Правило: один пункт = один PR = регрессионный тест + полный прогон
> `python tests/run_all.py`.

## Легенда

- **B** — польза: `5` падение/потеря данных/безопасность, `4` заметная ошибка,
  `3` корректность/поддерживаемость, `2` полировка, `1` косметика.
- **C** — сложность: `S` до ~0.5 дня, `M` 1–3 дня, `L` больше 3 дней,
  `XL` архитектурная переделка.
- **Q1** — высокая польза / низкая сложность; **Q2** — высокая / средняя-высокая;
  **Q3** — средняя / средняя-высокая; **Q4** — не сейчас.

## Заблокировано решениями (не пункты бэклога)

1. **Лицензия** (MIT/Apache-2.0) — без неё нельзя закрыть A-14 и принимать PR.
2. **Внешние CI/CD и сервисы** — не используем: только чистый git,
   локальный `python tests/run_all.py` и при желании нативный
   `.git/hooks/pre-push`. Никаких внешних API и облачных пайплайнов.
3. **Прод** — решение «не отслеживаем»; следствие: CSS на `yarbp.tech` может
   отличаться от репозитория. В репозитории остаётся только относительный путь
   шрифтов (Q1-04); никаких деплой-манифестов и серверных конфигов.
4. **Browser baseline** — без него нельзя выбирать полифилы; Q2-09.

## Definition of Done для любого пункта

- добавлен регрессионный тест (golden/feature/perf);
- `python tests/run_all.py` зелёный;
- документация/CHANGELOG обновлены;
- `console.log`/`console.debug` не коммитятся; `warn`/`error` — только для
  реальных ошибок;
- комментарии объясняют «почему», а не пересказывают код;
- нет новых runtime-зависимостей;
- обратная совместимость: сначала диагностика, потом изменение поведения;
  если AST меняется — версия/директива;
- один коммит не смешивает несколько крупных пунктов.
